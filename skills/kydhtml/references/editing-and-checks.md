# 편집과 검증

## 기존 자료 수정

1. 실제 완성 HTML과 이를 만드는 소스를 찾아 읽는다. 파일명만 보고 오래된 생성 스크립트를 실행하지 않는다. 별도 주제 파일·테마·상호작용 파일이 있는지 확인한다.
2. 사용자가 말한 페이지의 번호와 제목을 대조한다. ‘63페이지 뒤’라면 현재 자료의 해당 장을 확인한 뒤 삽입한다. 이전 대화의 번호가 이미 바뀌었을 수 있다.
3. 범위가 큰 변경 전에는 작업 폴더에 원본을 보관한다. 소스와 결과 HTML을 함께 반영해 다음 빌드가 수정을 지우지 않게 한다.
4. 새 장의 글자·그림·메모를 같은 흐름으로 추가한다. 기존 장의 내용은 요청 없이 다시 쓰지 않는다.
5. `data-go="59"` 같은 숫자 이동, `aria-label`의 장 번호, 메모의 장 번호, 초기 위치, 목차를 함께 확인한다. 새 엔진에서는 고정 ID를 사용하고 번호는 표시할 때 계산한다.
6. 앞 장·새 장·뒤 장을 함께 확인한다. CSS가 `nth-child`에 의존하면 삽입 후 다른 장의 모양이나 동작이 바뀌지 않는지도 본다.

시작 파일은 슬라이드 내부의 `template.speaker-note`를 사용한다. 장을 복사할 때 해당 장의 ID도 새로 부여하고 메모까지 수정한다. 기존 엔진을 이 구조로 강제로 바꾸지 않는다.

## 시작 파일의 사용법

- `assets/starter.html`을 출력 폴더로 복사한다. `lang`, 문서 제목, 표지, 단원명, 내용, 수업 메모, 복사용 문장을 연수에 맞게 바꾼다.
- 각 `section.slide`에 고유 `id`와 `data-title`을 둔다. 목차는 자동으로 생성된다.
- 슬라이드 이동 버튼은 `data-jump="슬라이드-id"`를 사용한다. URL의 `#3` 같은 숫자 위치도 지원한다.
- 수업 메모는 그 장 안의 `template.speaker-note`에 일반 텍스트로 쓴다. 학생 화면에는 나타나지 않는다.
- `#copy-data` JSON에 복사할 원문을 넣고, 버튼의 `data-copy` / `data-view`가 해당 키를 가리키게 한다. JSON 생성 시 `</`를 `<\/`로 이스케이프한다. JSON을 문자열 이어 붙이기로 잘못 인코딩하지 않는다.
- 데모의 버튼·체크·점수는 예시 구현이다. 주제에 불필요하면 관련 마크업과 핸들러를 함께 제거한다. 새 데모를 추가하면 별도 ID나 컨테이너로 범위를 제한한다.
- 외부 링크 예시는 실제 체험 링크로 바꾸고, 새 탭 설정을 확인한다. 예시 내용이 남아 있는지 최종 검색한다.

시작 파일은 글꼴이나 이미지를 다운로드하지 않는다. 원본 자료의 Jua/Gowun Dodum처럼 특정 서체가 필요하면 허가된 파일과 라이선스를 확보해 포함한다. 부분 글꼴은 새로 추가한 글자도 포함하는지 확인한다. 인터넷 글꼴 다운로드 실패 때문에 결과 파일이 갑자기 크게 늘었다면 용량과 대체 글꼴을 검토한다.

## 정적 검사

`scripts/check_html.py`는 파일을 실행하지 않고 다음을 확인한다.

- 슬라이드 수, 제목과 고유 ID, 내부 이동 대상
- 중복 ID, 복사·보기 버튼의 JSON 키, JSON 문법
- 새 탭 링크의 설정, 실행에 필요한 외부 자산
- 선택적으로 인라인 JavaScript의 Node 문법 검사

오류가 없다는 것은 레이아웃과 모든 기능이 정상이라는 뜻이 아니다. 경고는 사용자의 의도에 맞는지 검토한다. 외부 자산을 명시적으로 쓰는 자료라면 해당 경고가 허용될 수 있다.

시스템 임시 폴더에 쓸 수 없는 환경이라면 `--temp-dir <작업폴더의 임시폴더>`를 지정한다. 검사 중 생성한 JavaScript 임시 파일만 정리하며 원본 HTML은 수정하지 않는다.

## 실제 동작과 시각 검사

- 사용 가능한 승인된 미리보기 도구로 변경한 장을 확인한다. 지원하지 않는 파일 URL이나 차단된 브라우저 접근을 다른 수단으로 우회하지 않는다.
- 큰 글씨가 카드나 무대 밖으로 나가지 않는지, 버튼이 줄바꿈으로 겹치지 않는지, 긴 제목·한글·URL이 읽히는지 본다.
- 첫 장·마지막 장 이동, 목차 선택, 해시 주소, 돌아가기 버튼을 확인한다. 텍스트 입력·한글 조합·대화상자 안에서는 발표 단축키가 작동하지 않아야 한다.
- 복사 허용 상태와 복사 거부 상태를 확인한다. 거부되어도 원문이 모두 선택되어 수동 복사가 가능해야 한다.
- 데모는 선택 전·실행 후·초기화를 확인한다. 모형 그림을 실제 작동하는 앱이라고 표시하지 않는다.
- 새 탭 링크는 목적지 주소와 설정부터 확인한다. 대상 사이트의 정상 동작까지 확인하지 않았다면 확인했다고 말하지 않는다.
- 애니메이션을 끄거나 동작 줄이기를 켜도 학습 내용이 읽혀야 한다.

검증 환경이 부족하면 접근 가능한 검사부터 완료한다. 예를 들어 정적 분석이나 DOM 동작 테스트를 수행할 수 있다. 오프라인 PDF 렌더링을 사용했다면 브라우저와 렌더링이 다를 수 있음을 알고 해석한다. 실제로 확인한 범위를 보고한다.

## PDF도 요청받은 경우

PDF 도구·스킬이 있을 때 해당 흐름으로 변환하고 확인한다. 한 슬라이드가 한 페이지가 되도록 하고, 배경과 큰 글씨를 보존한다. 모든 슬라이드를 출력하도록 설정하며 현재 보이는 한 장만 출력하지 않게 한다.

애니메이션과 입력·투표·복사 버튼은 정적인 장면으로 바뀐다. 과정 설명에서 빠지는 단계가 있으면 정적인 단계 장면으로 펼치거나 적절한 상태를 선택한다. 실제 링크는 유지할 수 있지만 JavaScript 동작을 PDF에서도 보장하지 않는다.

PDF 페이지 수, 잘린 글자, 빈 페이지, 링크를 확인한다. HTML의 CSS Grid와 오프라인 PDF 엔진의 배치가 다를 수 있으므로 PDF 전용 조정을 HTML 화면 전체에 섣불리 적용하지 않는다. 변환을 위해 기존 자료의 운영 링크·코드·애니메이션을 제거하지 않는다.
