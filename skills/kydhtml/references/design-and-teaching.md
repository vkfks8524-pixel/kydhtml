# 디자인과 수업 구성

## 이 스킬이 재사용하는 특징

이 스타일은 코드 경험이 없는 중학생을 위한 HTML·프론트엔드·백엔드·실습 자료에서 발전했다. 사용자가 특히 원했던 것은 큰 글씨, 직관적인 그림, 친절한 진행 순서, 부드럽고 둥근 디자인이다. 이모지와 하단 상시 툴바는 제거했다. 이를 기본값으로 삼되 새 대상이나 명시된 브랜드 스타일에 맞게 조정한다.

`assets/style-reference.png`는 당시 자료의 MVP 설명·실습 부분을 모은 실제 렌더링이다. 색, 밀도, 타이포그래피와 관계도를 참고한다. 이미지 속 페이지 번호·문구·MVP 주제를 새 수업에 그대로 복제할 필요는 없다.

## 시각 기준

| 요소 | 기본값 / 적용 기준 |
|---|---|
| 무대 | 1600×900, 동일 비율로 화면에 맞춤 |
| 여백 | 좌우 약 88px, 위아래 48~64px |
| 제목 | 60~76px, 핵심 단어만 강조, 보통 1~2줄 |
| 본문 | 34~42px, 짧고 말하기 쉬운 문장 |
| 카드 제목 | 38~45px, 한눈에 구별되는 명칭 |
| 주요 버튼 | 32~36px, 클릭 결과를 알 수 있는 동사 |
| 작은 표지 | 단원명·단계 번호 정도만, 약 28~30px |
| 잉크 / 포인트 | #44364e / #7059a7 |
| 배경 / 보조색 | #fff9f5 / #e6dcff / #ffe0d2 / #d8f1e6 |
| 모서리 | 큰 카드 28~40px, 작은 요소 16~24px |
| 움직임 | 등장 약 0.5~0.8초, 긴 장식 움직임은 최소한 |

밝은 카드 안에는 충분히 진한 글씨를 쓴다. 흐린 라벤더색 본문을 흰 배경에 놓아 대비가 약해지지 않도록 한다. 정보가 많아지면 다음 장으로 넘긴다. 출처 URL, 개발 구현 설명, 운영상 주의사항을 작은 글씨로 바닥에 쌓지 않는다.

## 장면을 고르는 기준

- **용어 소개**: 큰 이름 + 쉬운 한 문장 + 눈에 보이는 예. 약자를 풀어 쓰되 영어를 외우는 시험처럼 구성하지 않는다.
- **역할 비교**: 같은 예시를 유지하고 2~3개 카드로 역할만 비교한다. 서로 다른 예시를 뒤섞어 비교 기준을 흐리지 않는다.
- **과정**: 3~4개 큰 단계와 방향을 보여 준다. 단계가 더 많으면 두 장 이상으로 나눈다.
- **요청·응답 / 여러 사용자**: 사용자, 서버, 저장소의 위치를 고정하고 이동 방향과 데이터 내용을 함께 보여 준다. 색만으로 의미를 구별하지 않는다.
- **상태 변화**: 버튼을 눌렀을 때 무엇이 달라졌는지 문장과 그림 모두에서 확인된다. 시연을 반복할 수 있게 초기화한다.
- **실습**: 행동 한 가지, 위치, 성공 화면을 중심으로 구성한다. 필요하면 ‘막혔을 때’ 장을 따로 둔다.
- **링크 모음**: 2~4개의 큰 카드. 제목은 읽히게, 주소 전체는 필요할 때만. 링크 수를 늘리기 위해 카드의 글씨를 계속 줄이지 않는다.
- **긴 프롬프트**: 화면에는 역할과 결과의 요약만 보여 주고, 원문은 복사·보기 창에 넣는다. 사용자가 제공한 내용을 임의로 줄이지 않는다.
- **마무리**: 실제 수행한 행동으로 확인한다. 예: 파일 저장, 실행, 한 번 수정, 수정 이유 설명.

## 설명과 실습을 연결하는 방식

한 수업에서 익숙한 예시를 이어 쓰면 학습자가 새 용어보다 관계에 집중할 수 있다. 기존 자료는 간식 선택, 농구 슛 게임, 단어 퀴즈를 각 단원의 목적에 맞게 썼다. 새 수업에서는 대상과 관련 있는 예시를 선택한다.

예를 들어 ‘처음부터 모두 만들기보다 작은 기능부터 만든다’는 수업이라면:

1. 실제 개발은 첫 요청 후 확인과 수정을 반복한다고 설명한다.
2. MVP를 ‘가장 중요한 기능이 실제로 작동하는 작은 첫 버전’으로 설명한다.
3. 이번 기능과 나중 기능을 구분하는 그림을 보여 준다.
4. 학습자가 자기 아이디어를 정하고 AI와 짧게 대화한다.
5. 파일로 실행하고, 바꿀 점 하나를 골라 다시 확인한다.

이 흐름은 반복 개선을 가르칠 때의 예시다. 모든 주제에 같은 목차를 강제하지 않는다.

## 내용과 사실을 구별하기

- 사용자의 프롬프트 원문, 공식 자료의 사실, 설명을 위한 예시를 구별한다.
- 메뉴나 주소가 실제와 다를 수 있는 모형은 예시라고 표시한다. 확인되지 않은 버튼 위치를 실제 스크린샷처럼 단정하지 않는다.
- 단일 HTML의 로컬 상태, 브라우저 저장, 서버의 여러 사용자 공유를 섞어 설명하지 않는다.
- ‘배포 개념만 설명’, ‘첫 실습만 추가’처럼 범위가 좁혀지면 그 범위를 따른다.
